# Экран «Тренировка и программы» (`HomeAndRoutinesScreen`)

**Маршрут:** `RouteTrain` (`IronLogRoot.kt`)  
**Файл реализации:** `app/src/main/java/com/example/ui/screens/HomeAndRoutinesScreen.kt`

---

## 1. Продуктовое описание

Главный экран приложения — точка входа, с которой пользователь начинает тренировку или управляет своими тренировочными программами.

### Основные пользовательские сценарии
1. **Обзор активности:**
   - В верхней hero-карточке отображается название приложения, бейдж автономной работы (`Офлайн / Offline`), кнопка открытия настроек (`settings_button`), общее количество завершённых тренировок и тренировочный объём за последние 7 дней в выбранных единицах (`кг` или `фнт`).
2. **Быстрый старт или возврат в тренировку:**
   - Если активной тренировки нет — отображается кнопка **«Начать пустую тренировку»** (`start_empty_workout_button`).
   - Если пользователь свернул/покинул текущую тренировку (например, системной кнопкой «Назад»), вместо старта появляется янтарная кнопка **«Продолжить»** с живым таймером (`resume_workout_button`).
3. **Фильтрация программ по папкам:**
   - Горизонтальная лента чипов `FilterChip`: «Все папки» и пользовательские/предустановленные папки с цветовым индикатором (`Сила / Strength`, `Гипертрофия / PPL` и др.).
   - Кнопка создания новой папки (`new_folder_button`) открывает диалог ввода названия.
4. **Работа с шаблонами тренировок (Routines):**
   - Карточка программы (`RoutineCard`) показывает папку, название, описание, первые 4 упражнения с целевыми `подходы×повторения` (и пометкой суперсета `[SS n]`, если привязано), а также кнопку **«Начать»** (`start_routine_<id>`).
   - Через меню `⋮` доступны: **Редактировать**, **Дублировать** (создаёт копию с суффиксом `(копия)` / `(copy)`), **Удалить** (soft-delete).
5. **Конструктор программ (`RoutineEditorDialog`):**
   - Позволяет задать название, описание, папку, добавить упражнения из каталога (`ExercisePickerDialog`), перемещать их вверх/вниз, объединять соседние упражнения в суперсет (`Link`), удалять и настраивать степперами (`−` / `+`) целевые подходы, повторения и время отдыха (шаг 15 сек, минимум 15 сек).

## 2. Техническое описание

### Входные состояния и потоки (`StateFlow`)
Экран получает данные из `IronLogViewModel`:
- `strings: AppStrings` — локализованные строки (`RU` / `EN`).
- `prefs: UserPreferences` — текущие единицы веса и язык.
- `exercises`, `folders`, `routines` — реактивные списки из Room (`Flow` → `StateFlow`).
- `activeWorkout: WorkoutSessionDto?` и `activeElapsedSec: Long` — состояние активной сессии.
- `completedWorkouts: List<WorkoutSessionDto>` — используется для подсчёта объёма за последние `7 × 24 × 3600 × 1000` мс через `StrengthCalculators.sessionVolumeKg`.

### Логика запуска тренировки
- При нажатии «Начать пустую тренировку» или «Начать» на карточке программы:
  1. `IronLogRoot` проверяет и при необходимости запрашивает разрешение `POST_NOTIFICATIONS` на Android 13+ (`TIRAMISU`), чтобы `WorkoutTimerService` мог показывать уведомление (при отказе сама тренировка и таймеры продолжают работать без ограничений).
  2. Вызывается `viewModel.startEmptyWorkout(onStarted)` или `viewModel.startWorkoutFromRoutine(routine, onStarted)`:
     - Проверяется, нет ли уже активной сессии в БД (`dao.getAllWorkoutsOnce().firstOrNull { it.session.isActive }`), чтобы исключить дубли активных тренировок.
     - При запуске из программы для каждого упражнения вызывается `repo.findPreviousExerciseSets(...)` — целевые веса и повторения автоматически предзаполняются из последней завершённой сессии (или из настроек шаблона, если истории ещё нет).
     - Сессия сохраняется в Room (`markSyncPending = false`, т.к. незавершённая тренировка на часы не уходит).
     - Устанавливается `_startingSessionFallback` в `IronLogViewModel`, чтобы UI мгновенно получил объект сессии ещё до первой эмиссии Room `Flow`.
     - Запускается `WorkoutTimerService.startWorkoutService(...)` и вызывается `onStarted()` → переход на `RouteActiveWorkout`.

### UX и адаптивность
- Контейнер `LazyColumn` ограничен `widthIn(max = 720.dp)` и выровнен по центру для корректного отображения на планшетах и складных экранах.
- Для числовых счётчиков и объёмов используется моноширинный стиль `MonoNumericTextStyle` (шрифт `JetBrains Mono`), предотвращающий «прыжки» ширины цифр при тике секундомера.
